2. RTL / Arabic-Specific Issues

SevIssueLocation
HIGH Nav active underline anchors on left-0 — should be right-0 in RTL to draw under the correct end of the Arabic text. after:left-0 in RTL visually places the indicator at the typographic end of the word. LandingPage.tsx : 201
HIGH College card arrow starts at translate-x-4 (positive = RTL right = visual left), so the animation direction is wrong. Arrow should start off-screen to the left in RTL (-translate-x-4) and enter from the right on hover. CollegesSection.tsx : 93
MED About-section floating card is positioned with -right-8 — in RTL "right" is the start side of the image. The decorative "١٠+ سنوات" badge should hang off the end (left) edge of the image, so it should use -left-8. LandingPage.tsx : 377
MED About section grid reverses order with order-2 lg:order-1 on the image and order-1 lg:order-2 on the text — this correctly places text on the right (start) at desktop. However on mobile (flex-col default) the image appears below the text, which is an unusual reading order for an RTL intro section. Text–then–image is non-standard for this layout pattern. LandingPage.tsx : 368, 386
MED Hero badge text is uppercase Arabic — CSS text-transform: uppercase has no effect on Arabic script and is a no-op. It is misleading and should be removed. LandingPage.tsx : 294
LOW Footer copyright bottom bar uses flex-col md:flex-row — on mobile the copyright and legal links stack vertically, but both are centered. This is fine. However items-center justify-between on desktop has the copyright on the right (RTL start) and buttons on the left (end). That is the correct RTL reading order, so this is fine — just noting it for clarity. LandingPage.tsx : 671

4. Code Quality Issues

SevIssueLocation
HIGH Inline <style dangerouslySetInnerHTML> block for animations — keyframes, skeleton styles, and media query overrides are injected as raw HTML. This bypasses React's styling system, cannot be tree-shaken or SSR-hashed, and could be moved to index.css or Tailwind config with no downside. LandingPage.tsx : 689–765
HIGH Hero overlay uses a raw inline style for a gradient — style={{ background: 'linear-gradient(...)' }}. Tailwind has bg-gradient-to-b with color stops; this should be a Tailwind utility or a CSS variable in the theme, not an inline style object. LandingPage.tsx : 288
HIGH The isLoading state is set to false synchronously at line 86 — setIsLoading(false) is called immediately inside useEffect with no actual async work. The comment says "Simulate data loading" — the loading state is a no-op and isLoading is always false by the time the first render paints. The skeleton in CollegesSection will never be shown. LandingPage.tsx : 85–86
MED ImageWithFallback is defined in LandingPage.tsx as a local component — it is used 9 times across the landing page. It should be extracted to a shared components/ui/ file so it can be reused elsewhere without duplication. LandingPage.tsx : 40–57
MED Responsive media queries inside dangerouslySetInnerHTML duplicate Tailwind classes. .hero-buttons { flex-direction: column } at 748 re-implements what flex-col sm:flex-row already does at line 309. The !important overrides on .stats-cards-row fight against the Tailwind grid classes. LandingPage.tsx : 744–762
MED Animation delays use custom CSS classes (.delay-100) in the inline style block instead of Tailwind's built-in delay-100/delay-200/delay-300 utilities which already exist. Redundant. LandingPage.tsx : 706–708
MED Lucide icons imported in LandingPage.tsx but also re-imported in CollegesSection.tsx — Monitor, Cog, Pill, BarChart2, PenTool, Zap, ArrowLeft are imported in both files. Not a bug, but since colleges data array owns JSX icons it tightly couples the data to the render library; icons should be string keys or components resolved at render time. LandingPage.tsx : 20–26 / CollegesSection.tsx : 2
LOW Stats and features arrays are defined inside the component body — they are constant data, not derived from props or state. They are re-created on every render. They should be moved outside the component or into a useMemo. LandingPage.tsx : 109–153
LOW Section-level z-30 on the Hero section — the hero section itself is z-30 while the navbar is z-[100]. The hero z-index is unnecessary since it's not overlapping anything and creates an unpredictable stacking context for child elements. LandingPage.tsx : 275

5. Performance / UX / Accessibility Issues

SevIssueLocation
CRIT No <main> landmark element. The page root is a plain <div>. Screen reader users cannot navigate directly to the main content area. The page should have a <main> wrapping everything below the <nav>. LandingPage.tsx : 156
HIGH Heading hierarchy is broken. The page jumps from <h1> (Hero) directly to multiple <h2>s then to mixed <h3>, <h4> tags. The "Why Choose Us" feature titles use <h4> (line 458) while being sub-content of a section <h2> — there are no intervening <h3>s. Screen readers and SEO crawlers see a broken outline. LandingPage.tsx : 299, 391, 446, 458
HIGH Mobile menu has no aria-expanded or role="navigation" — the hamburger button (line 219) toggles the menu but exposes no state to assistive technology. aria-expanded on the button and role="navigation" (or aria-label) on the menu <div> are missing. LandingPage.tsx : 219–228, 241–261
HIGH Background <video> has no aria-hidden="true" — decorative media should be hidden from the accessibility tree. Screen readers may announce it as an interactive video element. LandingPage.tsx : 278
MED Google Fonts loaded via @import url(...) in CSS — this is the slowest way to load web fonts (blocks CSSOM construction). Should be a <link rel="preconnect"> + <link rel="stylesheet"> in index.html, or better, self-hosted fonts. src/index.css : 1
MED The scroll event listener at line 70 has no throttle or passive: true flag — running setIsScrolled on every scroll event without throttling forces React re-renders at up to 60–120fps. Should use { passive: true } and debounce/throttle. LandingPage.tsx : 70
MED Gallery images have no loading="lazy" set on the wrapping parent. ImageWithFallback does add loading="lazy" at line 55, but the fallback <div> it renders on error has no equivalent lazy boundary — not a huge issue but worth noting for consistency. LandingPage.tsx : 44–51
LOW Stat cards use key={i} (array index as key) — since the stats array never reorders this is harmless today, but it is an antipattern. A stable key (e.g. the label string) should be used. LandingPage.tsx : 340
