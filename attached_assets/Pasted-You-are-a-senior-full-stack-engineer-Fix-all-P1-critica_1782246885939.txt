Current bug: the CORS callback has a fallback `callback(null, true)` that allows
ALL origins when none of the allowed-origin checks match. This is a security hole.

Fix: change the fallback to reject unknown origins:
  - If origin is in allowedOrigins list → callback(null, true)
  - If no origin header (same-origin / server-to-server) → callback(null, true)
  - ALL other cases → callback(new Error('Not allowed by CORS'))

Keep the existing Vercel preview URL regex check. Just fix the fallback.

FIX 5 — LOGOUT: REPLACE REDIS BLACKLIST WITH tokenVersion
═══════════════════════════════════════════════════

Redis is absent in the current environment. The token blacklist is silently
skipped, meaning logout does NOT invalidate access tokens.

The schema already has `tokenVersion` on the User model. Use it exclusively:

### 5a. On logout (auth.controller.ts → logout function):
  await prisma.user.update({
    where: { id: req.user.id },
    data: { tokenVersion: { increment: 1 } }
  });
  // Also delete the RefreshToken record as before.

### 5b. In auth middleware (auth.middleware.ts):
  After decoding the JWT, add:
  const user = await prisma.user.findUnique({ where: { id: decoded.id },
                                              select: { tokenVersion: true } });
  if (!user || user.tokenVersion !== decoded.tokenVersion) {
    return res.status(401).json({ message: 'Token has been invalidated' });
  }

### 5c. When generating the JWT (login / refresh):
  Include tokenVersion in the payload:
  jwt.sign({ id: user.id, role: user.role, tokenVersion: user.tokenVersion }, ...)

### 5d. Remove all `if (redis) { ... }` blacklist blocks.
  They are dead code now.
