FIX 1 — IDOR: Registration Approve/Reject Scope Check
═══════════════════════════════════════════════════

File: backend/src/controllers/auth.controller.ts
Functions: approveRegistration (around line 301) and rejectRegistration (around line 364)

PROBLEM:
A COLLEGE_ADMIN can approve or reject ANY registration request — even ones
belonging to a different college. The controller looks up the request by ID
but never checks if the request's collegeId matches the admin's managed college.

FIX for approveRegistration:
After fetching the registration request by ID, add a scope check:

  const request = await prisma.registrationRequest.findUnique({
    where: { id: requestId },
    include: { college: true }
  });

  if (!request) {
    return res.status(404).json({ message: 'Registration request not found' });
  }

  // Scope check — COLLEGE_ADMIN can only approve requests for their college
  if (
    req.user.role === 'COLLEGE_ADMIN' &&
    req.user.managedCollegeId !== request.collegeId
  ) {
    return res.status(403).json({ message: 'Access denied: request belongs to a different college' });
  }

  // DEPARTMENT_ADMIN can only approve requests for their department
  if (
    req.user.role === 'DEPARTMENT_ADMIN' &&
    req.user.managedDepartmentId !== request.departmentId
  ) {
    return res.status(403).json({ message: 'Access denied: request belongs to a different department' });
  }

Apply the EXACT same scope check logic to rejectRegistration.

SUPER_ADMIN bypasses all scope checks (no restriction needed for them).

FIX 2 — IDOR: Student Detail / Update / Delete Scope
═══════════════════════════════════════════════════

File: backend/src/controllers/students.controller.ts
Functions: getStudentById (line ~131), updateStudent (line ~166), deleteStudent, toggleStudentStatus

PROBLEM:
These functions look up a student by ID but never verify the requesting admin
actually manages the college/department that student belongs to.
A COLLEGE_ADMIN from College A can view/edit/delete students from College B.

FIX — create a reusable scope-check helper at the top of the file:

  async function assertStudentScope(
    student: { collegeId: number | null; departmentId: number | null },
    user: { role: string; managedCollegeId?: number | null; managedDepartmentId?: number | null }
  ): Promise<boolean> {
    if (user.role === 'SUPER_ADMIN') return true;
    if (user.role === 'COLLEGE_ADMIN') {
      return student.collegeId === user.managedCollegeId;
    }
    if (user.role === 'DEPARTMENT_ADMIN') {
      return student.departmentId === user.managedDepartmentId;
    }
    return false;
  }

Then in getStudentById, updateStudent, deleteStudent, and toggleStudentStatus,
AFTER fetching the student, add:

  const allowed = await assertStudentScope(student, req.user);
  if (!allowed) {
    return res.status(403).json({ message: 'Access denied: student belongs to a different scope' });
  }

Make sure the initial student fetch includes collegeId and departmentId
so the scope check has the data it needs.

FIX 5 — Socket.IO: Add tokenVersion Check
═══════════════════════════════════════════════════

File: backend/src/socket/ (wherever the Socket.IO auth handshake is defined)

PROBLEM:
The Socket.IO handshake verifies the JWT signature but does NOT check
tokenVersion. A user who has been force-logged-out (tokenVersion incremented)
can maintain an active socket connection indefinitely.

FIX — in the socket auth middleware, after verifying the JWT:

  socket.use(async (packet, next) => {
    try {
      const token = socket.handshake.auth?.token;
      if (!token) return next(new Error('No token'));

      const decoded = jwt.verify(token, process.env.JWT_SECRET!) as any;

      // tokenVersion check — same logic as HTTP auth middleware
      const user = await prisma.user.findUnique({
        where: { id: decoded.id },
        select: { tokenVersion: true, isActive: true }
      });

      if (!user || !user.isActive) return next(new Error('User not found or inactive'));
      if (user.tokenVersion !== decoded.tokenVersion) {
        return next(new Error('Token invalidated — please log in again'));
      }

      socket.data.user = decoded;
      next();
    } catch (err) {
      next(new Error('Invalid token'));
    }
  });

If the socket auth is done differently (e.g. in the 'connection' event handler),
adapt the same tokenVersion check to whatever pattern is already used.
